01 The Problem — Original chaos-jungle (RENCI) motivation
WHAT EXISTED
BPF / XDP
Silent TCP/UDP payload corruption — swaps two byte positions in kernel, recomputes checksum
TC / netem
Delay · loss · duplication · reordering
Documentation only — no code, no automation
Storage Corruption
Bit-flip files matching a glob pattern via dd + crontab scheduling
WHAT WAS MISSING
No Python API
Manual scripts — cannot import or integrate into code
No Revert
TC/BPF rules stay loaded on crash — manual cleanup
No Composition
Cannot combine faults — each tool is independent
No Measurement
No baseline vs fault comparison — manual interpretation
No Remote Control
Must run on target machine — no SSH, no daemon
No Safety
Everything needs sudo — no dry-run, no danger levels
02 chaos-jungle — The New Version overview
A tool that lets you deliberately break your system in a controlled way — before your users do it for you.
Simulates real-world failures
Slow networks · crashed services · corrupted files · unresponsive LLM APIs — on demand, reproducibly
Runs safely
Everything is automatically cleaned up when done — even on crash or exception, via finally block
Measures the impact
Compares how your system behaves normally vs under failure — quantitative deltas and quality gates
Works anywhere
Your laptop · remote server · machine behind a firewall — any OS for LLM/transport faults
Full observability
Every action logged to SQLite — web dashboard, CSV export, CLI — complete audit trail
Built for research
HPC workflows · LLM agent resilience · distributed systems · scientific pipelines

07 Measurement & Results quantifying impact
MEASUREMENT LIFECYCLE
runner.measure(workload, n_baseline=5, n_fault=5)
① Baseline runs→ ② Inject faults→ ③ Fault runs→ ④ Stop faults→ ⑤ Compute delta
BUILT-IN METRICS
PingLatency
avg / min / max RTT to a host
CommandMetric
Any shell command — parse stdout to dict
FileIntegrity
File count + md5 diff under fault
ThroughputMetric
curl download speed measurement
ScriptMetric
Run a local or remote script, parse stdout as metrics
MEASUREMENT RESULT
result.baseline → dict of baseline metrics
result.fault → dict of fault metrics
result.delta → % change per metric key
result.passed(key, 0.9) → True / False
result.passed_quality() → faithfulness gate
result.passed_oracles() → oracle assertions
result.summary() → human-readable text

08 Safety & Assertions staying in control
SAFETY POLICY
SafetyPolicy — gatekeeper before anything runs
max_danger
0 = network only · 1 = CPU/memory · 2 = kill/corrupt
dry_run
Log commands without executing — safe preview mode
allowed_targets
Whitelist of hosts that can be targeted
GUARDRAILS
ConflictError
Two tc netem faults on same interface → blocked before start
Live State Check
Existing tc rules from a previous run → blocked
Suite Validation
Incompatible scenarios running in parallel → warned
Auto-Revert
Every fault reverted in finally block — even on crash
ORACLE ASSERTIONS
Binary pass/fail checks on workload results
Oracle(lambda r: r["retries"] < 5, "max 5 retries")
Oracle(lambda r: r["success_rate"] > 0.9)
runner.measure(workload, oracles=[o1, o2])
result.passed_oracles() → True / False
TRACE CAPTURE & REPLAY
Trace Capture
Record all LLM API calls during a fault session
Trace Replay
Replay captured traces to reproduce exact failure conditions
